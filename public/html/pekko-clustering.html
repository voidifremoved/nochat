Apache Pekko Clustering

Comparing peer discovery mechanisms for Pekko clusters: Kubernetes API vs Hazelcast.

Kubernetes API

Uses Kubernetes API server to query for pods with specific labels.

+ Native to K8s + No extra infra - RBAC setup needed
application.conf
rbac.yaml
pekko.management {
  cluster.bootstrap {
    contact-point-discovery {
      discovery-method = kubernetes-api
      service-name = "my-pekko-service"
      required-contact-point-nr = 2
    }
  }
}
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "watch", "list"]

Hazelcast (Alternative)

Uses Hazelcast IMDG for node discovery, useful when not running on K8s or spanning multiple environments.

+ Environment agnostic + Cross-datacenter - Heavy dependency
application.conf
hazelcast.xml
pekko.discovery {
  method = hazelcast
  hazelcast {
    config-file = "hazelcast.xml"
  }
}
pekko.management.cluster.bootstrap {
  contact-point-discovery {
    discovery-method = hazelcast
  }
}
<hazelcast>
  <network>
    <port auto-increment="true">5701</port>
    <join>
      <multicast enabled="true"/>
    </join>
  </network>
</hazelcast>
