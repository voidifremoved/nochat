Large Language Models typically default to outputting walls of Markdown. While great for text and basic code snippets, Markdown falls flat when describing complex spatial systems, comparing multiple approaches, or showing interactive flows.

Inspired by [Thariq's post on the effectiveness of HTML](https://thariqs.github.io/html-effectiveness/), I experimented with prompting LLMs to produce self-contained, interactive HTML files instead of static text.

Below are two examples of how this approach transforms technical explanations.

## Example 1: Comparing Clustering Approaches (Apache Pekko)

When evaluating architectural decisions, we often need to compare options side-by-side, look at pros/cons, examine diagrams, and read configuration code. A markdown file forces this into a linear read.

By asking the LLM for a self-contained HTML file, we get a much richer artifact.

### The Prompt

```text
I am evaluating how to handle peer discovery for an Apache Pekko cluster.
I need to compare using the Kubernetes API approach versus using Hazelcast.

Please write a self-contained HTML file (with inline CSS and JS) that provides a
side-by-side comparison. The HTML should include:
1. A brief summary of each approach.
2. Pros and cons formatted cleanly with tags.
3. Simple, inline SVG diagrams showing how nodes discover each other in both scenarios.
4. An interactive tabbed interface for each approach showing the required code
   snippets (e.g., application.conf and RBAC yaml for K8s, application.conf
   and hazelcast.xml for Hazelcast).

Do not output any markdown, only the raw HTML.
```

### The Result

Instead of scrolling through pages of text, the output is a compact dashboard. You can click the tabs to swap between configuration files while keeping the context in view.

## Example 2: Visualizing Microservice Architecture

Diagrams in markdown usually require rendering an image or using Mermaid (which can be visually limiting). For architecture, sometimes you need to see different states or variants of a system.

### The Prompt

```text
I need to understand different strategies for routing and load balancing in a
clustered microservices architecture.

Please create a single, self-contained HTML file (using inline CSS, JS, and SVG)
that provides an interactive visualization.

Requirements:
1. Provide three architectural variants: 'API Gateway', 'Service Mesh', and
   'Client-side Load Balancing'.
2. Provide a row of buttons at the top to toggle between these three variants.
3. Use inline SVG to draw the nodes (Client, Load Balancer, Gateway, Services,
   Proxies, etc.) and edges connecting them.
4. Animate the edges (e.g., dashed lines moving) to show the flow of traffic.
5. Make the SVG nodes clickable. When a node is clicked, display details about
   that component in a panel below the diagram.

Make it visually appealing and clean. Return only the raw HTML.
```

### The Result

This output is incredibly effective. Not only do you get vector graphics that scale perfectly, but you can actually interact with the architecture. Toggling between API Gateway and Service Mesh instantly redraws the diagram, making the differences immediately obvious.

## Automating this with an Agent Skill

Writing out those lengthy prompts every time you want a visualization can be tedious. To solve this, you can give your AI agent a "Skill" file—a set of standing instructions that teaches it exactly how to format these interactive HTML documents without needing to be told every time.

I have created a comprehensive skill file that you can download and provide to any agent. It instructs the agent to automatically build the high-fidelity dashboards seen above (complete with TL;DR boxes, decision matrices, interactive SVG animations, and deep-dive inspectors) whenever you ask for an architectural explanation or system comparison.

## Conclusion

By treating HTML as the output medium, we can turn LLMs into rapid prototyping engines for explanations, design docs, and interactive learning tools. By equipping your agent with the provided skill file, generating these rich assets becomes entirely automatic.
